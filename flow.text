  PUBLIC USER AUTH (Supabase)
  ---------------------------

      |
      v
  AuthModal (components/auth/AuthModal.jsx)
      +-- Sign Up  -> supabase.auth.signUp()  -> email confirmation
      +-- Sign In  -> supabase.auth.signInWithPassword()

      |
      v
  SupabaseAuthContext stores session + user
      +-- AuthContext wraps extra profile/role data
      |
  RequireAuth checks:
      +-- Session present -> allow route
      +-- No session -> open AuthModal -> redirect after success


  ADMIN AUTH (Custom JWT)
  -----------------------
  POST /api/auth/login  { username, password }
      |
      v
  server/routes/auth.js
      +-- Validate credentials against SQLite staff table
      +-- Issue JWT (signed with JWT_SECRET)
      +-- Return { token, user, permissions }
      |
  Frontend stores token in localStorage
      |
  ProtectedRoute reads token -> checks permissions -> renders or redirects
      |
  All admin API calls include: Authorization: Bearer <token>
  server/middleware.js verifies token on protected routes

9. BOOKING LIFECYCLE
================================================================================

  1.  User selects tour -> /tour/:id
  2.  Clicks "Book Now" -> RequireAuth check
  3.  If unauthenticated -> AuthModal -> Supabase sign-in
  4.  Authenticated -> /booking/:id
  5.  MultiTravelerBooking wizard:
        Step 1 -> collect traveler info
        Step 2 -> select date, number of travelers
        Step 3 -> payment details -> POST /api/payments
        Step 4 -> booking created -> POST /api/bookings
  6.  Booking record saved to SQLite (bookings table)
  7.  Payment record saved (payments table)
  8.  Confirmation screen shown to user
  9.  Admin sees booking in /admin/bookings
  10. Admin can update booking status, view full details in /admin/bookings/:id

12. BUILD & DEPLOYMENT FLOW
================================================================================

  DEVELOPMENT
  -----------
  Terminal 1: npm run dev          -> Vite dev server on :5173
  Terminal 2: node server/index.js -> Express API on :5000
  Vite proxies /api/* -> :5000 (configured in vite.config.js)

  PRODUCTION
  ----------
  npm run build                    -> Vite outputs /dist
  node server/index.js             -> Express serves /dist (SPA fallback)
                                      + handles all /api/* routes
  Deployment target: Render.com
  +-- Web service: node server/index.js
  +-- Static files: dist/ served by Express
  +-- Persistent disk: uploads/ directory

  DATABASE INITIALIZATION
  -----------------------
  On server startup -> runSeed() checks if DB is empty
  If empty -> seed.js populates all tables with sample data
  Manual seed: GET /api/seed
